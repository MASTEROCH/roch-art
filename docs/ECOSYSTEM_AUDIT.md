# Экосистема ROCH — аудит, итерация 1

**Дата:** 14.11.2026 · **Основа:** чтение кода пяти репозиториев (ничего не менялось), живые страницы, прогон стража каталога · **Сопутствующие файлы:** `ECOSYSTEM_INTEGRATION_CONTRACT.md`, `catalog/services.json`, `catalog/check.mjs`

## 0. Коротко

1. **Продукты живые, но говорят разными голосами.** Страж каталога нашёл 36 противоречий (ошибок) и 19 мёртвых строк (предупреждений). При этом все 21 закреплённая цена в коде ROCH AI и Motion совпадают с каталогом: расходятся тексты и обещания вокруг цен, а не сами цены.
2. **Самый дорогой риск — деньги в ROCH AI.** Оплата Stars проходит, даже если база не ответила: человек видит «зачислено», а на сервере ничего не начислено. Проверка суммы пропускает платёж без суммы. Журнала платежей с пользователем и суммой нет.
3. **Воронку почти не видно.** Событий нет нигде, кроме Motion. Сайт шлёт события в приостановленный ROCH Audit, и два из четырёх типов там молча отбрасываются.
4. **Переходы к услугам рвутся.** CTA «Обсудить в Telegram» после аудита сайта возвращает человека в тот же бот. На AppHUB и Motion из ROCH AI не ведёт ничего. AppHUB не ссылается на ROCH вообще.
5. **Для Decision Intelligence фундамент уже есть.** У ROCH AI — кнопка «⭐ Сделать эталоном» в ленте Романа. У ROCH Audit — готовая методология (`generate-block.ts`). В памяти ROCH 1000+ решений с «почему» и отвергнутыми вариантами.

## 4. Что может сломать действующие покупки и доступы

**ROCH AI**
- **База выключена или упала** → `successful_payment` не начисляет, но пишет «✅ зачислено» (`webhook/route.ts:77,89`). Купленное живёт только в localStorage и CloudStorage, которые человек может править.
- **Начисление упало после отметки платежа** → повтор от Telegram игнорируется. Спасает только уведомление Роману.
- **Проверка суммы** `paid && paid !== stars` пропускает платёж без суммы. Секрет вебхука в production задан — проверено по именам переменных Vercel, — поэтому подделка снаружи закрыта. Но проверку надо сделать строгой.
- **`roch_payments` хранит только `charge_id`.** Нет пользователя, пакета и суммы — сверить и вернуть деньги не из чего; `/paysupport` и возврата нет.
- **Расходы без оплаты.** Веб-гости делают безлимитные разборы на Opus. `artifactOnly` и polish бесплатны и без авторизации. `/api/tma/spy` и `/api/tma/shot` открыты: первый засыпает ленту Романа, второй — запуск браузера на каждый запрос. `/api/project` скачивает любой URL без запрета внутренних адресов (SSRF).
- **Общие таблицы.** `~/code/AppBrandHUB` содержит ту же миграцию и тот же бот. Если он смотрит в ту же базу, `roch_ai_users` общая.
- **Проверить в панели Supabase**, что проект активен: в `docs/roch-ai-intake.md` он «на паузе» с 30.09. Переменные в Vercel есть, саму базу без секретов отсюда не проверить.

**ROCH Motion**
- MCP выдаёт новинки владельцам «Навсегда», у которых истёк год новинок: проверка `life` вместо `covers()` (`store/api/mcp.js:59,64`).
- Защита от повтора платежа не атомарна (`SET`, а не `SET NX`): два одновременных повтора пройдут оба.
- Деплой из `store/` вместо `dist/store/` подхватит устаревший `private/config.json` (11 900, без волн) и манифест на 345.
- **Нельзя менять:** `id` механик, список `free`, даты волн, форму payload счёта, уровни — права покупателей привязаны к ним.

**roch-art.com**
- Аналитика, чекаут /vibe, персона чата и счётчик слотов живут на деплое **приостановленного** ROCH Audit. Выключить его — сломать сайт.

## 6. План конверсии

### 6.1 CTA Router (ROCH AI)

**Правила:**
1. Одно предложение на ответ, и только после того, как человек получил пользу.
2. Не чаще одного предложения услуги за 24 часа. Самостоятельный путь всегда рядом и визуально не слабее.
3. Никаких предложений при отказе, низкой уверенности модели и в первом разборе бесплатного пользователя.
4. Без пугающих слов: формулировка — что станет лучше, а не что сломается.
5. Тексты и цены берутся из `catalog/services.json`, а не из промпта. Модель называет проблему, Router выбирает продолжение. Каждый показ и клик пишет `trigger`.

| Момент (`trigger`) | Сигнал | Одно продолжение | Самостоятельный путь |
|---|---|---|---|
| `ai.idea_draft.done` | вердикт go / rework | «Превратить идею в живой прототип» → `packaging` $1 560 | «Докрутить черновик самому» |
| `ai.idea_draft.unclear` | много «уточнить» | «Разобрать идею с Романом за 2 часа» → `unpacking` $480 | «Ответить на вопросы и пересобрать» |
| `ai.screen.refined_twice` | 2+ «Докрутить» по одному экрану, Trust ≤ 5 | «Профессиональная доработка интерфейса» → `packaging` | «Ещё «Точечно»» |
| `ai.retention.low` | Retention ≤ 4 в разборе продукта | «Разобрать удержание с Романом» → `unpacking`; глубокий аудит — после решения D4 | «Посмотреть механики удержания» → Motion `loyalty` / `reward` |
| `ai.site.large_scope` | аудит сайта, объём large | «Запуск под ключ» → `apphub_express` (**вместо тупика «Обсудить в Telegram»**) | «Сделать сначала главное по списку» |
| `ai.quota.empty` | баланс 0 | пакеты Stars — **не консультация** | приглашение друга (+1) |
| `ai.power_user` | 2+ покупки или Pro второй месяц | «Позвать Рому лично» (уже есть) → `lead.created` | — |

### 6.3 ROCH Motion: пять трений из кода
1. **Купить вне Telegram нельзя.** Кнопка ведёт в бот, а просмотры на вебе не считаются (`витрина.html:3527`).
2. **Тяжёлая загрузка.** 4,27 МБ JS (1,49 МБ в gzip) плюс 1,2 МБ CSS; все 385 механик грузятся разом.
3. **27 фильтров в одном ряду**, нет сортировки по назначению. Ценность («Почему цепляет») спрятана за кнопкой «i»: только 39 из 385 текстов говорят о деловом результате.
4. **Лишние шаги перед оплатой:**
   - бесплатное — только после сторис;
   - «второй шанс» перед счётом;
   - на сценарии главная кнопка продаёт весь набор.
5. **Ответ об оплате.** Если вебхук отвечает дольше ~6,7 с, человек видит «Сначала купите механику». Плюс блок пакета на 30.

## 7. ROCH Decision Intelligence — архитектура

```
 knowledge/ (git, версии)          eval/ (git)                    Supabase (ROCH AI)
 ├─ principles.md                  ├─ cases/*.json  5 учебных     ├─ roch_feedback
 ├─ ux-rules.md                    │                + 1 проверочный ├─ roch_kb_items (черновики)
 ├─ anti-patterns.md   ──┐         ├─ checks.ts  объективные     └─ roch_prompt_versions
 ├─ gamification.md      │         └─ run.ts     прогон
 ├─ retention.md         ├─► сборка промпта ──► Claude ──► ответ ──► лента Романа
 ├─ hypotheses.md        │   (статичный блок         │                ✅ ❌ ✏️ 💬 ⭐ 🆚
 └─ cases/ (private)   ──┘    в кеше + 2–3 примера   │                    │
                              по типу задачи)        └── прогон eval ◄─────┘ новая версия промпта
```

**1. База знаний.** Файлы в репозитории ROCH AI, а не в базе: версии, ревью, откат.
- **Источники:**
  - рамка ROCH Audit (`generate-block.ts:75` — Skin · Mechanic · Engine, 5 движков, 10 анти-паттернов, карта метрик);
  - канон ROCH (`mem.py канон <тема>`, 667 переносимых решений);
  - лог решений с «почему» и отвергнутыми вариантами.
- **Не сваливать целиком:** в промпт идут 2–3 правила и пример под тип задачи (экран, сайт, идея). Статичная часть — в кешируемом блоке; сейчас кешируется только промпт паспорта.

**2. Формат before/after (`eval/cases/*.json`):**
```json
{ "id": "case-001", "privacy": "private|internal|public", "input": {"kind": "screen", "ref": "…"},
  "problem": "…", "options": [{"id":"A","desc":"…"},{"id":"B","desc":"…"}], "chosen": "B",
  "reasoning": "почему B, почему не A", "expected_effect": "…",
  "measured": {"metric": "…", "before": null, "after": null, "source": null},
  "tags": ["trust","onboarding"], "approved_by": "roman", "version": 1 }
```
- **Набор:** пять учебных и шестой проверочный, который в промпт не попадает. Их выбирает Роман из короткого списка, собранного из лога решений, — следующая итерация. Чужие кейсы без разрешения не используются.
- **Признак `privacy`:** `private` — только для оценки; `internal` — можно как пример в промпте; `public` — можно показывать пользователям, только с разрешения.

**3. Оценка — три слоя, которые не смешиваются в одну цифру.**
- **Объективные проверки** (код, каждый прогон):
  - формат и три слоя на месте, оценки в диапазоне;
  - цены только из каталога, нет слов из стоп-листа страха;
  - каждое утверждение об элементе ссылается на видимый элемент — проверяет второй проход.
- **Экспертная оценка** (Роман, 1–5): корректность диагноза, понимание цели интерфейса, реальная проблема, релевантность исправления, качество UX, реализуемость, польза для клиента, отсутствие выдуманного.
- **Предпочтение вкуса** («лучший из двух»): отдельный счёт. Красивое и правильное — разные оси.
- **LLM-судья** допускается только для объективных критериев и только после совпадения с оценками Романа ≥ 80 % на наборе.

**4. Петля обратной связи.** Под каждой картинкой «после» в ленте Романа, рядом с существующей «⭐ Сделать эталоном»:
- ✅ Одобрить · ❌ Отклонить · ✏️ Исправить · 💬 Почему ошибка · 🆚 Лучший из N · 📥 В базу;
- «Исправить» и «Почему» — ответом-реплаем, текст сохраняется;
- «В базу» создаёт черновик кейса с `privacy = private`;
- **весов модели не трогаем:** изменение = новая версия промпта или базы → прогон набора → выпуск, только если результат не хуже прошлой версии;
- смена модели — тот же прогон.

**5. SQL-черновик** — не применён, нужна миграция с «да» Романа:
```sql
create table roch_feedback (
  id bigserial primary key, created_at timestamptz default now(),
  exemplar_id bigint references roch_exemplars(id), prompt_version text,
  verdict text check (verdict in ('approve','reject','fix','explain','best_of')),
  note text, best_choice text, promoted boolean default false
);
create table roch_prompt_versions (id text primary key, created_at timestamptz default now(), notes text, eval_score jsonb);
alter table roch_feedback enable row level security;  -- политики не создаём: только service role
```
**Приватность:** материалы пользователей сами в базу не попадают. Перенос — только по явному разрешению человека к конкретному разбору. По умолчанию разрешения нет.

## 8. ROCH Audit — три варианта

| Критерий | A · отдельный сервис | B · методология в ROCH AI | C · режим в ROCH AI + roch-audit.com как посадочная |
|---|---|---|---|

| Сопровождение | два продукта, две оплаты | один продукт | один продукт + страница |
| Дублирование | полное (аудит и там, и там) | нет | нет |
| Вероятность монетизации | низкая: на паузе, четыре набора цен | выше: есть аудитория и оплата Stars | как B, плюс B2B-вход |
| Ясность для человека | «два аудита ROCH — какой мой?» | один вход | один вход, отдельная дверь для B2B |
| B2B-продажи | есть, но без трафика | слабее (бот) | лучше всех |
| Риски миграции | — | низкие: пользователей и платежи не переносим | низкие, но **нельзя трогать `vibe-*`** — на них живёт roch-art |

**Рекомендация: B сейчас, C — только по данным.**
1. Перенести в ROCH AI рамку, схему Quick Read и наложения Deep / Master как платный режим «Глубокий аудит» на тех же Stars. Цена — решение Романа.

3. Вынести `vibe-*` в roch-art или ROCH AI, прежде чем когда-либо выключать Audit.
4. Вернуться к C, когда режим «Глубокий аудит» наберёт устойчивый спрос: порог, например 20 покупок в месяц, — тоже решение Романа.

A не рекомендую: второй стек и вторая оплата ради продукта без трафика.

**Не переносить:** пользователей, платежи, ключи Upstash, `products/*.zip`, черновые юридические тексты.
